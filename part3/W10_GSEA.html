1. Introduction: The Threshold Problem

ORA Limitation Explanation
Cutoff dependency Genes with padj=1e-10 and padj=0.049 are treated identically
Direction ignored Information about up- vs. down-regulation is discarded
Boundary problem If all genes in an important pathway have padj=0.06, ORA misses it entirely

✅ Solution: GSEA

  • Uses all genes, ranked by a continuous metric
  • No cutoff required → no information loss
  • Preserves directionality of expression change

2. The GSEA Algorithm

1) Input: Ranked Gene List

Ranking metric options:

Metric Formula Characteristics
log2FoldChange Used directly Simple; focuses on effect size
Wald Statistic (recommended) DESeq2 stat column Integrates LFC + uncertainty
Pi-value \(-\log_{10}(p) \times \text{sign}(LFC)\) Emphasizes statistical significance
TipWhich Ranking Metric Should I Use?

All three metrics are highly correlated (r > 0.9), but in general:

  • Wald statistic: Accounts for both effect size and its standard error → most balanced choice
  • Pi-value: Emphasizes genes with strong statistical support
  • Best practice: run all three and compare (sensitivity analysis)

2) Enrichment Score (ES) Calculation

A running sum is calculated for each gene set as you walk through the ranked list:

Walk through all genes from rank 1 to N:
  → Hit a gene IN the pathway:  running sum += 1/K  (K = pathway size)
  → Hit a gene NOT in pathway:  running sum -= 1/(N-K)

ES = maximum deviation of the running sum from zero (KS statistic)

Patterns of ES:

Up-regulated pathway:   ^^^^^^^\_____  → peak near the top
Random (not enriched):  ~/\/\/\/\/\/\  → fluctuates around zero
Down-regulated pathway: _______/^^^^^  → peak near the bottom

3) Statistical Significance: Permutation Test

1. Calculate ES from the actual data
          ↓
2. Randomly shuffle sample labels 1,000 times
          ↓
3. Generate 1,000 random ES values → build null distribution
          ↓
4. Where does the observed ES fall relative to the null?

NES (Normalized Enrichment Score): \[NES = \frac{ES_{observed}}{\text{mean}(ES_{random})}\] Corrects for pathway size differences → enables fair comparison across pathways

FDR (q-value): \[\text{FDR} = \frac{N_{>NES\text{ in random}}}{N_{>NES\text{ in observed}}}\]

For GSEA, you typically need to convert Gene Symbols or Ensembl IDs to Entrez IDs.

library(tidyverse)
library(org.Hs.eg.db)
library(AnnotationDbi)

# Load DESeq2 results
res        <- readRDS('examples/data/w7_res_DESeq2.rds')
res_df <- as.data.frame(res) %>%
  filter(!is.na(pvalue) & !is.na(log2FoldChange)) %>%
  mutate(gene = rownames(.))

# Example: Gene Symbol → Entrez ID
my_ids <- res_df$gene  # vector of Gene Symbols

my_entrez <- mapIds(
  org.Hs.eg.db,
  keys      = my_ids,
  column    = "ENTREZID",  # desired output ID type
  keytype   = "SYMBOL",    # input ID type
  multiVals = "first"      # handle 1-to-many mappings: keep first
)

# Combine into a data frame for inspection
my_genes <- tibble(
  gene   = my_ids,
  entrez = my_entrez
)
head(my_genes)

# check for NAs (novel genes, pseudogenes, version mismatches, etc.)
sum(is.na(my_genes$entrez))
my_genes %>% filter(is.na(entrez))

① Data Loading

library(clusterProfiler)
library(enrichplot)
library(msigdbr)

# 1. Load DESeq2 results
res_shrink <- readRDS('examples/data/w9_res_DESeq2_lfcShrink.rds')
res        <- readRDS('examples/data/w7_res_DESeq2.rds')  # needed for stat column

# 2. Convert to data frame and remove NAs
res_df <- as.data.frame(res) %>%
  filter(!is.na(pvalue) & !is.na(log2FoldChange)) %>%
  mutate(gene = rownames(.))

# 3. Add Entrez ID
res_df <- res_df %>% left_join(my_genes, by = "gene")

# 4. Compute ranking metrics
res_df$rank_lfc  <- res_shrink$log2FoldChange
res_df$rank_pi   <- -log10(res_df$pvalue) * sign(res_df$log2FoldChange)
res_df$rank_wald <- res_df$stat

# Check correlation between metrics
cat("LFC vs Pi-value:", round(cor(res_df$rank_lfc, res_df$rank_pi,  use = "complete"), 3), "\n")
cat("LFC vs Wald:    ", round(cor(res_df$rank_lfc, res_df$rank_wald, use = "complete"), 3), "\n")
cat("Pi  vs Wald:    ", round(cor(res_df$rank_pi,  res_df$rank_wald, use = "complete"), 3), "\n")

# 5. Remove duplicate Entrez IDs and drop NAs
res_df <- res_df %>%
  distinct(entrez, .keep_all = TRUE) %>%
  filter(!is.na(entrez))

# 6. Build the final ranked gene list (using Wald statistic)
geneList        <- res_df$rank_wald
names(geneList) <- res_df$gene   # use when keyType = "SYMBOL"
geneList        <- sort(geneList, decreasing = TRUE)

cat("\nTop 5 (up-regulated):\n");   print(head(geneList, 5))
cat("\nBottom 5 (down-regulated):\n"); print(tail(geneList, 5))

② Running GSEA

# ---- (1) GO Biological Process ----
gsea_go <- gseGO(
  geneList     = geneList,
  OrgDb        = org.Hs.eg.db,
  keyType      = "SYMBOL",
  ont          = "BP",         # choose from: BP, MF, CC
  minGSSize    = 10,           # exclude very small pathways
  maxGSSize    = 500,          # exclude very broad, non-specific pathways
  pvalueCutoff = 1,            # keep all results for now; filter later
  by           = "fgsea"       # fast approximation method
)
saveRDS(gsea_go, 'examples/analysis/w10_gsea_GO.rds')
# ---- (2) Reactome ----
library(ReactomePA)

# Note: Reactome requires Entrez IDs!
geneList_entrez        <- res_df$rank_wald
names(geneList_entrez) <- res_df$entrez
geneList_entrez        <- sort(geneList_entrez, decreasing = TRUE)

gsea_reactome <- gsePathway(
  geneList     = geneList_entrez,
  pvalueCutoff = 1
)
saveRDS(gsea_reactome, 'examples/analysis/w10_gsea_reactome.rds')

4. Summary

ORA vs. GSEA Comparison

Feature ORA GSEA
Input DEG list + background All genes, ranked
Cutoff required Yes (binary) No (continuous)
Statistical test Hypergeometric / Fisher’s Exact Permutation test (KS statistic)
Effect direction Ignored Preserved (up vs. down)
Effect size metric Odds Ratio, Fold Enrichment NES (Normalized Enrichment Score)
Advantage Intuitive, fast No information loss, direction-aware
Disadvantage Cutoff-sensitive, loses information Computationally intensive, harder to interpret
Best used when Clear, well-defined DEG list exists Exploratory analysis, detecting subtle changes
Caution❌ Pitfalls or common mistakes to avoid
  1. No background gene set (ORA): Always use the actually-tested genes, not the whole genome
  2. Duplicate Entrez IDs: Use distinct(entrez, .keep_all = TRUE) to deduplicate
  3. Not removing NAs: Filter out NA pvalue/log2FoldChange before building the ranked list
  4. Cutoff shopping: Adjusting thresholds until you get the desired result = p-hacking
  5. Ignoring gene set size: Set minGSSize = 10 and maxGSSize = 500 to exclude trivial pathways
  6. Reporting NES without FDR: Always check FDR (q-value) ≤ 0.25 (GSEA standard) or ≤ 0.05 (conservative)

1. Threshold Effect in ORA

Run enrichGO(BP) twice using different gene lists from the same DESeq2 results:

  • List A (Strict): padj < 0.01 & |log2FC| > 2
  • List B (Lenient): padj < 0.05 & |log2FC| > 0.5
library(clusterProfiler)
library(org.Hs.eg.db)

# List A — Strict
genes_A <- res_df %>%
  filter(padj < 0.01, abs(log2FoldChange) > 2) %>%
  .$gene

ora_A <- enrichGO(
  gene         = genes_A,
  universe     = total_genes,   # always set background!
  OrgDb        = org.Hs.eg.db,
  keyType      = "SYMBOL",
  ont          = "BP",
  pvalueCutoff = 0.05,
  qvalueCutoff = 0.2
)

# List B — Lenient
genes_B <- res_df %>%
  filter(padj < 0.05, abs(log2FoldChange) > 0.5) %>%
  .$gene

ora_B <- enrichGO(
  gene         = genes_B,
  universe     = total_genes,
  OrgDb        = org.Hs.eg.db,
  keyType      = "SYMBOL",
  ont          = "BP",
  pvalueCutoff = 0.05,
  qvalueCutoff = 0.2
)

dotplot(ora_A, showCategory = 5) + ggtitle("Strict (List A)")
dotplot(ora_B, showCategory = 5) + ggtitle("Lenient (List B)")

1) Compare the top 5 pathways. Did the biological conclusion change?
2) Why might List A fail to detect broad biological pathways compared to List B? (Hint: think about the number of genes fed into Fisher’s test)
