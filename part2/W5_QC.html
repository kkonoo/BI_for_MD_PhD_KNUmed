Workflow of RNA-seq Data Analysis

The overall workflow of RNA-seq analysis is as follows (Conesa et al., Genome Biol., 2016):

  1. Read trimming
  2. Alignment
  3. Quantification
  4. Normalization
  5. Differential analysis
  6. Functional profiling

0) Quality Check: FastQC

  • Per base sequence quality:
    check quality toward the 3' end
    verify that scores remain in the green zone
  • Per sequence GC content:
    should follow a normal distribution
    multiple peaks? … contamination
  • Adapter Content: determines whether trimming is necessary
  • Number of reads: check Q20/Q30 ratios

1) Read Trimming: TrimGalore

# TrimGalore key functions
# 1) Remove low quality reads (Phred score Q20, error rate 1%) - sliding window
# 2) Remove adapter sequences (Illumina Universal, TruSeq/Nextera)
# 3) Minimum length filtering - discard reads that are too short

2) Alignment: STAR

  • Bowtie2/BWA: for DNA; indexing & mismatch-based
  • STAR: spliced aligner dedicated to RNA-seq
    • Recognizes splice junctions → maps to exons only
    • Requires high RAM (>30GB)
  • QC criterion (general): %Uniquely mapped reads > 80%, #mapped reads > 20M
  • Output format: SAM (text) or BAM (binary)
  • Galaxy: web-based tool for pre-processing

3) Quantification

Alignment-based (STAR + featureCounts)

  • Traditional approach: position indexing → mapping to reference
  • Requires BAM files; computationally intensive

Alignment-free / Pseudo-alignment (Salmon, Kallisto)

  • Uses short k-mer (k=31) compatibility checks instead of full read mapping

  • No BAM required; very fast

  • Multi-mapping reads → isoform-level probabilities assigned via EM algorithm

    • e.g., read A → isoform X (0.6), isoform Y (0.4)
Tiptximport using salmon outputs (transcripts)
  1. aggregation: transcripts –> gene
  2. correction: average transcript length per sample (isoform switching) –> gene count correction
  3. import: float number –> integer

4) Filtering and Normalization

Filtering examples (depending on your study)

  • Remove low-count genes: remove genes with zero counts in ≥ N×0.5 samples (N: the smallest group)
  • Remove confounding genes:
    • Mitochondrial (^MT-)
    • Ribosomal (^RPS|^RPL)
    • Immunoglobulin (^IG[HKL])

Why Normalization is Needed

  • Library size (depth): higher sequencing depth → higher counts
  • Gene length: longer genes → higher counts

Normalization Methods Comparison

Method Correction Comparison Remarks
Raw Count × × edgeR/DESeq2 input
RPKM/FPKM Depth + Length Intra-sample Deprecated
TPM Depth + Length Intra + Inter-sample per-sample sum = 1M
CPM Depth Inter-sample
TMM/RLE Depth + Composition Inter-sample Standard for DEG analysis

# 7. visualization ####
## 7-1. reshaping counts (Long format for ggplot) ####
transform_to_long <- function(count_matrix, method_name) {
  as.data.frame(count_matrix) %>%
    rownames_to_column("Gene") %>%
    pivot_longer(-Gene, names_to = "Sample", values_to = "Count") %>%
    mutate(Method = method_name,
           # Log2 transformation (pseudocount: +1 for 0)
           LogCount = log2(Count + 1))
}

TMM vs RLE

  • TMM: selects a reference sample, trims extreme values, and normalizes based on a set of housekeeping genes
  • RLE: uses the median ratio of each gene relative to its geometric mean across samples as the size factor
